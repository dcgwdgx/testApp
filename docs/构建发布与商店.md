# 构建发布与商店

## 版本与应用标识

- 对外版本：`app.config.js` 中的 `expo.version`，当前为 `1.0.1`。
- Android 包名：`com.petportrait.ai`。
- iOS Bundle ID：`com.petportrait.ai`。
- Android 版本号：优先读取 `ANDROID_VERSION_CODE`。
- iOS 构建号：优先读取 `IOS_BUILD_NUMBER`。
- App Store Connect 应用 ID：`6772645981`。

## EAS 构建配置

`eas.json` 定义以下构建配置：

| 配置 | 用途 |
| --- | --- |
| `development` | 带开发客户端的内部构建 |
| `preview` | 内部分发；Android 产物为 AAB |
| `production` | 商店发布构建 |
| `simulator` | iOS 模拟器内部构建 |

Android 的生产提交配置指向 `production` 轨道，并将发布状态设置为 `draft`。自动流程还有一个备用脚本会直接更新生产轨道并使用 `completed` 状态，因此每次自动提交后必须在 Play Console 核对实际结果。

## GitHub Actions

### Android

`.github/workflows/android-build.yml` 在 `master` 分支发生相关代码变更时运行：

1. 安装 Node.js 20、Java 17、依赖和 EAS CLI。
2. 使用 `preview` 配置在 Linux 上本地构建 AAB。
3. 使用 `github.run_number` 作为 Android 版本号。
4. 优先调用 `eas submit` 提交 Google Play。
5. 如果 EAS 提交失败，调用 `scripts/google-play-upload.js` 作为备用方式。
6. 把 AAB 保存为 GitHub Actions 构建产物。

所需仓库密钥：

- `EXPO_TOKEN`。
- `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON`。

### iOS

`.github/workflows/ios-build.yml` 在 `master` 分支发生相关代码变更时运行：

1. 使用 macOS、Node.js 20 和指定的 Xcode 版本。
2. 使用 `production` 配置本地构建 IPA。
3. 使用 `github.run_number` 作为 iOS 构建号。
4. 调用 `eas submit` 提交 TestFlight。
5. 把 IPA 保存为 GitHub Actions 构建产物。

所需仓库密钥：`EXPO_TOKEN`，以及 EAS/Apple 侧已经配置的有效提交凭据。

### iOS 模拟器

`.github/workflows/ios-sim-build.yml` 只支持手动触发，使用 `simulator` 配置生成调试用模拟器构建。

## 手动构建

```powershell
eas build --platform android --profile production
eas build --platform ios --profile production
```

手动提交：

```powershell
eas submit --platform android --profile production
eas submit --platform ios --profile production
```

提交前确认构建号尚未被商店使用，并按[测试清单](测试清单.md)完成验证。

## 应用内商品

| 商品 ID | 类型 | 积分 |
| --- | --- | ---: |
| `gen_10_1` | 消耗型 | 10 |
| `gen_30` | 消耗型 | 30 |
| `gen_60` | 消耗型 | 60 |

App Store Connect 和 Google Play Console 中必须使用完全相同的商品 ID。当前没有订阅商品。商品价格以商店后台配置和商店返回的本地化价格为准；代码价格只是备用展示。

发布新版本时沿用这些商品。只有在商品 ID、积分数量或计费模式确实变化时才新建商品。

## Google Play 商品详情

最终素材位于 `store-assets/final`。默认 `en-US` 商品详情使用：

- 5 张手机截图。
- 5 张 7 英寸平板截图。
- 5 张 10 英寸平板截图。
- 1 张 1024×500 置顶大图。
- 可选 YouTube 预览视频。

更新步骤：

1. 运行 `npm run store:assets`。
2. 人工检查文字、宠物身份一致性、尺寸、排序和价格描述。
3. 在 Play Console 更新短说明、完整说明和图片。
4. 对生成或编辑过的素材完成 AI 资源声明。
5. 保存后进入“发布概览”，确认变更数量和内容。
6. 提交审核，并记录日期和审核结果。

Google Play 只接受公开或“不公开列出”的 YouTube 视频地址；仓库 MP4 不能直接填入。视频必须关闭广告和年龄限制。

## 发布后检查

1. 在真实商店页面确认版本、文案、截图和置顶大图。
2. 使用测试账号安装或更新正式包。
3. 验证三个商品都能返回正确的本地价格。
4. 完成一次沙盒购买，确认积分只发放一次。
5. 验证免费次数、积分扣减、生成、保存、分享和历史。
6. 检查 Play Console、App Store Connect 和 GitHub Actions 是否有错误或政策警告。
